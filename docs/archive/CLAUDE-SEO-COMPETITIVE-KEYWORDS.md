## 전략 배경

자사 브랜드 키워드(torr rf, britzmedi)는 쉬운 싸움이고 우선순위 낮음.
진짜 중요한 것: **경쟁사가 이미 1페이지를 점령하고 있는 메인 키워드를 뚫는 것**.

피부미용기기(aesthetic RF device) 업계에서 구매자/의사결정자가 검색하는 핵심 키워드를 선점해야 한다.

## 1. 키워드 전략 재설계

### 기존 Tier 시스템 폐기 → 새로운 분류

```
Category A: 시술명 (Procedure Keywords)
  - 시술을 알아보는 의사/클리닉이 검색
  - 우리 기기로 가능한 시술과 연결

Category B: 기전/기술명 (Technology Keywords)  
  - RF 기술의 원리를 찾는 전문가
  - 우리 기술의 차별점 어필 기회

Category C: 제품/장비명 (Equipment Keywords)
  - 장비 구매를 고려하는 의사결정자
  - 가장 직접적인 구매 의도

Category D: 시장/비즈니스 (Market Keywords)
  - 유통/파트너십을 찾는 바이어
  - B2B 리드 전환 핵심

Category E: 비교/평가 (Comparison Keywords)
  - 구매 전 비교하는 사람들
  - 전환율 가장 높은 키워드

Category F: 문제/솔루션 (Problem-Solution Keywords)
  - 환자/클리닉의 고민에서 출발
  - 롱테일이지만 전환 의도 높음
```

## 2. 경쟁사 벤치마킹

### 주요 경쟁사 (이 회사들이 1페이지 점령 중)
```
- InMode (Morpheus8, BodyTite)    → 공격적 SEO + 콘텐츠 마케팅
- Cynosure (TempSure)             → 브랜드 인지도
- BTL (Vanquish, Exilis)          → B2B 콘텐츠
- Cutera (truSculpt)              → 임상 데이터 기반
- Solta Medical (Thermage)        → 역사적 브랜드 파워
- Syneron Candela (Profound RF)   → 전문가 타겟
```

### GSC에서 경쟁사 분석하는 방법
```
1. 우리가 노출은 되는데 클릭이 없는 키워드 = 경쟁사가 상위에 있는 것
2. impressions 높고 clicks 0인 키워드 = 가장 큰 기회
3. 이 키워드들의 순위 변화를 주 단위로 추적
```

## 3. GSC 데이터 수집 개선

### 3.1 기존 수집 방식 수정

현재: 50개 타겟 키워드만 매칭
변경: **GSC에서 모든 쿼리를 수집 + 타겟 키워드 매칭 + 신규 기회 키워드 발견**

```typescript
// src/cron/weekly-collect.ts 수정

async function collectGSCData(env: Env) {
  const gsc = new GSCService(env);
  
  // 1. 전체 쿼리 데이터 수집 (상위 5000개)
  const allQueries = await gsc.fetchSearchPerformance({
    startDate: getDateDaysAgo(10),
    endDate: getDateDaysAgo(3),
    dimensions: ['query', 'page', 'country', 'device'],
    rowLimit: 5000
  });
  
  // 2. 타겟 키워드 매칭 (100개)
  for (const row of allQueries.rows) {
    const matchedKeyword = matchToTargetKeyword(row.keys[0], targetKeywords);
    if (matchedKeyword) {
      // 기존 로직: keyword_rankings에 저장
      await saveRanking(env.DB, matchedKeyword.id, row);
    }
  }
  
  // 3. 매칭 안 된 쿼리 중 유의미한 것 = 신규 기회 키워드
  //    impressions > 10 이고 타겟에 없는 쿼리 → discovered_keywords 테이블
  for (const row of allQueries.rows) {
    if (!matchedToAny && row.impressions > 10) {
      await saveDiscoveredKeyword(env.DB, row);
    }
  }
  
  // 4. 모든 수집 데이터를 raw_gsc_data에도 보관 (트렌드 분석용)
  await saveRawGSCData(env.DB, allQueries.rows);
}
```

### 3.2 새 DB 테이블

```sql
-- 100위권 밖에서 서서히 올라오는 것도 추적
-- position이 없어도 impressions만 있으면 의미 있음

-- 모든 GSC 수집 데이터 보관
CREATE TABLE IF NOT EXISTS raw_gsc_data (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  query TEXT NOT NULL,
  page TEXT,
  country TEXT DEFAULT 'ALL',
  device TEXT DEFAULT 'ALL',
  position REAL,
  impressions INTEGER DEFAULT 0,
  clicks INTEGER DEFAULT 0,
  ctr REAL DEFAULT 0,
  collected_week TEXT NOT NULL,  -- '2026-W07' 형식
  collected_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 신규 발견 키워드 (타겟 리스트에 없지만 유의미한 쿼리)
CREATE TABLE IF NOT EXISTS discovered_keywords (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  query TEXT NOT NULL UNIQUE,
  best_position REAL,
  total_impressions INTEGER DEFAULT 0,
  total_clicks INTEGER DEFAULT 0,
  first_seen TEXT,           -- '2026-W07'
  last_seen TEXT,
  suggested_category TEXT,   -- 자동 분류 시도
  status TEXT DEFAULT 'new' CHECK(status IN ('new', 'added', 'ignored')),
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 주간 순위 변화 요약 (트렌드 추적 핵심)
CREATE TABLE IF NOT EXISTS weekly_progress (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  keyword_id INTEGER REFERENCES target_keywords(id),
  week TEXT NOT NULL,          -- '2026-W07'
  position REAL,
  prev_position REAL,
  change REAL,                 -- 양수 = 상승(좋음), 음수 = 하락
  impressions INTEGER,
  clicks INTEGER,
  ctr REAL,
  milestone TEXT,              -- 'entered_top100', 'entered_top50', 'entered_top10', 'first_page'
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  UNIQUE(keyword_id, week)
);

CREATE INDEX IF NOT EXISTS idx_raw_gsc_query ON raw_gsc_data(query);
CREATE INDEX IF NOT EXISTS idx_raw_gsc_week ON raw_gsc_data(collected_week);
CREATE INDEX IF NOT EXISTS idx_weekly_keyword ON weekly_progress(keyword_id);
CREATE INDEX IF NOT EXISTS idx_weekly_week ON weekly_progress(week);
CREATE INDEX IF NOT EXISTS idx_discovered_status ON discovered_keywords(status);
```

## 5. 구현 순서

### Step 1: SEO Workers 수정 (britzmedi-seo)
1. 새 DB 테이블 3개 생성 (raw_gsc_data, discovered_keywords, weekly_progress)
2. 기존 target_keywords 시드 교체 (50개 → 100개)
3. weekly-collect.ts 수정 (전체 쿼리 수집 + 매칭 + discovered)
4. 주간 progress 자동 계산 로직 추가
5. 새 API 추가:
   - GET /api/progress — 주간 프로그레스 요약
   - GET /api/progress/weekly — 주별 히스토리
   - GET /api/keywords/:id/history — 개별 키워드 12주 히스토리
   - GET /api/discovered — 신규 발견 키워드
   - POST /api/discovered/:id/add — 발견 키워드 → 타겟 추가
6. GET /api/briefs 개선 (순위 JOIN)
7. wrangler deploy

### Step 2: britzmedi-global API 프록시 추가
1. /api/admin/content-hub/seo/progress.ts
2. /api/admin/content-hub/seo/history/[id].ts
3. /api/admin/content-hub/seo/discovered.ts

### Step 3: Content Hub UI
1. SEOOverviewBar.tsx — 상단 요약
2. Progress 탭 + ProgressTracker.tsx
3. SEOBriefCard.tsx 개선 (순위 데이터 표시)
4. KeywordDetailModal.tsx (12주 히스토리 차트)
5. DiscoveredKeywords.tsx (신규 발견 키워드)
6. PositionBadge.tsx (순위 뱃지)

### Step 4: 빌드 + 배포
1. npm run build
2. git commit + push
3. SEO Workers wrangler deploy
4. 수동 collect 실행하여 데이터 확인

## 6. 주의사항

- 기존 content_items, content_revisions 테이블 건드리지 않기
- 기존 Pipeline, All Content, Quality 탭 기능 유지
- SEO Workers 연결 실패해도 다른 기능 정상 작동
- 100개 키워드 시드 교체 시 기존 rankings 데이터도 정리 필요
- GSC에서 5000개 쿼리 수집은 Workers 실행 시간 고려 (30초 제한 → 필요시 배치 처리)
- Recharts 또는 Chart.js로 순위 트렌드 차트 (가벼운 라이브러리 사용)
